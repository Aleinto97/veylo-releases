# Media3 FFmpeg audio extension

The app packages the four vendored `androidx.media3.decoder.ffmpeg` Java classes and `apps/veylo-dx/android/jniLibs/<selected-abi>/libffmpegJNI.so` in **both** debug and release. ExoPlayer/MediaCodec owns video; this library is audio-only. The checked-in extension targets Media3 1.11.1 and FFmpeg 6.0, with Android API 31 for new builds and 16 KiB ELF alignment.

The optional rebuild workflow is:

```sh
./tools/media3-ffmpeg/fetch-sources.sh
./tools/media3-ffmpeg/build-ffmpeg-audio.sh
./tools/media3-ffmpeg/build-jni-glue.sh
```

Read the scripts before rebuilding. They use the Android NDK sysroot, keep static libraries under `ffmpeg-src/` and put JNI outputs in `build-jni/<abi>/`. `ANDROID_NDK_HOME` overrides the default SDK location; `VEYLO_BUILD_JOBS` defaults to two. Downloaded source/build trees are ignored.

Copy `build-jni/<abi>/libffmpegJNI.so` to `apps/veylo-dx/android/jniLibs/<abi>/`. Select `VEYLO_ANDROID_ABI=armeabi-v7a` for 32-bit TVs, or leave it unset for ARM64. JNI outputs strip debug sections before packaging. Copy exactly `FfmpegAudioDecoder.java`, `FfmpegAudioRenderer.java`, `FfmpegDecoderException.java`, `FfmpegLibrary.java` and the package metadata from the pinned AndroidX source directory. Exclude `ExperimentalFfmpegVideoRenderer.java`: this build enables audio decoders only. Update `packaged_audio_library_sha256_by_abi[<abi>]` (the original ARM64 hash remains a fallback) in `sources.json` after verifying the new library; Rebuild the app (`dx build --platform android`) and check AC3/E-AC3 playback. This is not a universal audio, passthrough, video, or HDR guarantee.

The Java extension comes from AndroidX Media (Apache-2.0); FFmpeg retains its own licence and configured codec obligations. Preserve source headers, licence files and build provenance. Rebuilding this library is separate from `scripts/build-native.sh`, which builds the Rust core/proxy/torrent/JNI runtime.

The preserved upstream licence texts are in `licenses/`; `sources.json` records pinned source identities and the packaged binary hash. Downloaded source/build caches were removed after verification and can be recreated with the fetch script.

`toolchain-shims/` is generated by the audio build. Its `libgcc.a` link points
to the selected local NDK and must not be checked into source control.
